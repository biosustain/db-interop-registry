Data Model

Overview

Interop DB tracks genes and strains from four collaborating databases (ALEdb, BiGGr, PanKB, PMKbase). Each entity is assigned a stable UID that bridges different naming conventions across sources.

Core Tables

Mapping

Maps a source-specific local ID to a universal UID.

  • Primary key: (source_db_id, entity_type_id, local_id)

  • uid: Stable SHA256-derived identifier (e.g. G-80D178D48AB8)

  • updated_at: Last modification timestamp

Example: ALEdb calls a strain 511145 (taxonomy ID), PanKB calls it GCF_000005845.2 (assembly ID). Both map to different UIDs, but are connected through synonyms.

Synonyms

Alternative identifiers that link to a UID.

  • Primary key: (uid, synonym)

  • updated_at: Creation timestamp

Example: UID S-95516EDB62D5 (local_id 1415167) has synonyms GCF_000497485.1 and GCF_023521615.1.

Searching by any synonym finds the associated entity.

Gene-Strain Relationship

Records which genes exist in which strains, as reported by source databases.

  • Primary key: (gene_uid, strain_uid, source_db_id)

  • updated_at: Last modification timestamp

Currently holds 164M+ relationships, primarily from PanKB.

Entity URL

Stores links back to source databases for each entity.

  • Primary key: (local_id, source_db_id, url_type, url)

Relationship URL

Stores links for gene-strain relationships.

  • Primary key: (gene_uid, strain_uid, source_db_id, url)

UID System

UIDs are generated by hashing a normalized form of the entity identifier:

  • Prefix: G- for genes, S- for strains

  • Hash: First 12 hex characters of SHA256

UIDs are stable — the same input always produces the same UID. Different local IDs from different sources produce different UIDs, which are then connected through the synonym system.
